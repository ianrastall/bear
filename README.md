# Bear

A UCI chess engine written in Rust.

The design is in [docs/architecture.md](docs/architecture.md): board representation, move generation, search, evaluation (hand-crafted first, then NNUE trained on Bear's own games), threading, the UCI loop, verification and the milestone roadmap.

## Status

Milestone M4 (selectivity) is in progress. Bear plays complete games of standard chess and Chess960 through any UCI interface. The search has a transposition table, staged move ordering and the usual pruning and reductions; the evaluation is still material and piece-square tables, so it is far from its target strength.

## Building

Requires the Rust toolchain named in `rust-toolchain.toml`; `rustup` installs it on first use.

```
cargo build --release
```

The engine is `target/release/bear` (`bear.exe` on Windows).

## Using it

Point a chess interface that speaks UCI at the `bear` binary. Supported commands: `uci`, `isready`, `ucinewgame`, `position`, `go` (`wtime`, `btime`, `winc`, `binc`, `movestogo`, `movetime`, `depth`, `nodes`, `infinite`), `stop`, `setoption`, `quit`.

| Option | Meaning |
|---|---|
| `Hash` | Size of the transposition table in megabytes. Default 16. |
| `Move Overhead` | Milliseconds kept back from the clock on every move for communication delay. Default 10. |
| `UCI_Chess960` | Write castling as king takes rook. Castling is accepted in either notation regardless. |

Debug commands: `d` prints the board, `eval` the static evaluation, `perft <depth>` the move counts, and `bench [depth]` searches a fixed set of positions and prints the total node count.

Arguments are run as one command, so `bear bench` prints the benchmark and exits.

## Checks

```
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo test --release -p bear-core --test mates
cargo run --release -p perft -- suite crates/perft/suites/standard.epd
cargo run --release -p perft -- suite crates/perft/suites/extended.epd
cargo run --release -p bear-uci -- bench
```

The bench node count identifies the engine's behaviour. Commits that change search or evaluation state the new count as `Bench: <nodes>` in the message, and CI checks it on Linux and Windows.

## Tools

```
perft <depth> [fen]                 count positions at <depth>
perft divide <depth> [fen]          the count below each legal move
perft suite <file> [--max-depth N]  check every line of an EPD file
perft fuzz --oracle <engine> [--positions N] [--depth D] [--seed S] [--chess960]
datagen openings --out <file> [--count N] [--plies P] [--seed S] [--depth D] [--max-cp C]
datagen mates --out <file> [--count N] [--max-mate M] [--plies P] [--seed S]
cargo xtask sprt --base <revision or engine file> [--new <engine file>] [--bounds <name>]
```

`perft fuzz` plays random games and compares the per-move counts of every position with another UCI engine's `go perft` output. The other engine is only run as a separate program.

`datagen openings` writes balanced random opening positions for test matches. `books/bear-8ply.epd` was made with `--count 2000 --seed 2026`.

`datagen mates` collects positions with a short forced mate from Bear's own games. `crates/engine-core/tests/mates.epd` holds 36 of them, and the release-mode test requires the search to find every one.

`cargo xtask sprt` plays the working tree (or `--new`) against an earlier revision with fastchess until a sequential probability ratio test accepts or rejects the change. fastchess is found through `--fastchess`, the `FASTCHESS` environment variable or the path.

## Layout

| Path | Contents |
|---|---|
| `crates/engine-core` | `bear_core`: board, attack tables, move generation, perft, evaluation, search, time management. |
| `crates/engine-uci` | The `bear` binary: UCI parsing, the reader and coordinator threads, bench. |
| `crates/perft` | The `perft` binary and its suites. |
| `crates/datagen` | The `datagen` binary. |
| `xtask` | Developer tasks. `cargo xtask find-magics` regenerates the slider magic numbers. |
| `books` | Opening positions generated by Bear. |
| `docs/architecture.md` | Architecture and implementation plan. |

Further crates (`engine-nnue`, `engine-bench`) are added in the milestones that give them content.
