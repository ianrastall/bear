# Bear architecture and implementation plan

Bear is a UCI chess engine in Rust (2024 edition). This document is the design the code is built against. All numeric search constants are starting values to be tuned, and Elo figures are estimates, not measurements.

## Licensing

- **Engine:** MIT, written clean-room. Ideas come from the Chess Programming Wiki and papers, never from pasted GPL source. Stockfish and several of the strongest open engines are GPLv3; porting code from them would make Bear GPLv3.
- **NNUE training data:** only data generated by Bear itself. Third-party datasets (Lc0, Stockfish-generated) carry their own terms and the rating lists' originality rules.
- **Borrowed data and tools:**
  - PeSTO's piece-square tables are published without a formal licence, so Bear does not use them. The bootstrap evaluation uses tables written for Bear, computed from a few simple rules, and the tuner in M5 replaces the numbers.
  - Opening books (the UHO family and similar) have informal terms; check them before redistributing. Using them locally is fine.
  - `fastchess` and `bullet` are MIT as far as known; confirm before depending on them. `cutechess-cli` and a Stockfish binary used as a perft oracle are GPL but only executed, never linked.
  - The `shakmaty` crates are GPL-3; Bear uses no chess-rules crate.

## Decisions at a glance

| Question | Decision |
|---|---|
| Make/unmake | **Copy-make**, 192-byte `Position` (3 cache lines) |
| Move | 16-bit `NonZeroU16`; ordering score lives in the move list, not the move |
| Castling encoding | King-takes-rook internally, so Chess960 works from day one |
| Sliders | Fancy magics, table generated by `build.rs` into `.rodata`; PEXT is opt-in (M8) |
| Legality | Pseudo-legal staged generation, lazy legality, dedicated evasion generator |
| TT | 16-byte XOR-validated entries, 4 per 64-byte cluster, plain `AtomicU64`, zero `unsafe` on the access path |
| CPU features | Compile-time tiers, one binary per tier; runtime detection only as a startup guard |
| SIMD | `std::arch` on stable, not nightly `std::simd` |
| Eval | Search is generic over `Evaluator`; HCE lives in core, NNUE in its own crate |
| Threads | `thread::scope` per `go`; long-lived state owned by the engine and lent to workers |
| Test runner | `fastchess` |

Deliberate departures from common practice:

- **Feature flags.** Cargo features cannot enable target features, so `bmi2`/`avx2`/`avx512`/`neon` are build tiers, not Cargo features.
- **SPRT bounds.** `[0, 5]` is a gain bound, not a non-regression bound. Used for refactors it would reject every neutral patch. See 7.2.
- **Killers, countermoves, check extension.** Implemented, but they are the first simplification candidates once continuation history and singular extensions land.
- **"Non-blocking" stdin.** Implemented as a dedicated blocking reader thread that never waits on the search. True non-blocking stdin is not portable.

## 1. Crate structure and workspace topology

```
bear/
├─ Cargo.toml              # [workspace], resolver = "3", edition = "2024"
├─ rust-toolchain.toml     # pinned stable (≥ 1.89, for stable AVX-512 intrinsics)
├─ crates/
│  ├─ engine-core/         # lib bear_core: types, attacks, position, movegen, search, tt, history, time, hce
│  ├─ engine-nnue/         # lib bear_nnue: net format, accumulator, SIMD inference; impl Evaluator
│  ├─ engine-uci/          # bin bear: protocol, options, coordinator, bench
│  ├─ engine-bench/        # criterion microbenches, bench positions, SEE/perft EPDs
│  ├─ perft/               # bin: perft, divide, suite runner, differential fuzzer
│  └─ datagen/             # bin: opening sets (now); self-play generation and Texel tuner (later)
├─ xtask/                  # cargo xtask: release tiers, sprt, find-magics, bench-check
├─ nets/                   # network files (default one embedded)
└─ books/                  # bear-8ply.epd, generated by `datagen openings`; third-party books are not committed
```

A crate is added to the workspace in the milestone that gives it real content; no empty placeholder crates.

**Dependency direction.** `engine-core` knows nothing about NNUE. It defines the seam:

```rust
pub trait Evaluator: Sized {
    fn reset(&mut self, pos: &Position);                    // full refresh at root
    fn push(&mut self, child: &Position, d: &DirtyPieces);  // called by make; O(1), records only
    fn pop(&mut self);
    fn evaluate(&mut self, pos: &Position) -> i32;          // centipawns, side to move
}
pub struct ThreadData<E: Evaluator> { /* … */ }
```

Until the NNUE arrives the trait has only `evaluate`; the hand-crafted evaluation recomputes from the board and needs no hooks. `reset`, `push` and `pop` are added in M7.

`engine-nnue` depends on `engine-core` and implements `Evaluator`. `engine-uci` instantiates `ThreadData<Nnue>`; `datagen` instantiates both `ThreadData<Hce>` and `ThreadData<Nnue>`. Everything is monomorphised, with no `dyn` in the search. PV and non-PV nodes are monomorphised the same way through a `NodeType` trait with `const PV: bool; const ROOT: bool`.

**Runtime dependencies.** `engine-core`, `engine-nnue` and `engine-uci` use `std` only. The one exception is optional `windows-sys`/`libc` behind `large-pages`. Dev dependencies are `criterion` and `proptest`.

**CPU features.** Hot loops must not branch on CPU capability, so the tier is fixed at compile time and code selects on `cfg(target_feature = "...")`.

| Tier (`cargo xtask release`) | `-C target-cpu` | Sliders | NNUE path |
|---|---|---|---|
| `x86-64-v2` | `x86-64-v2` | magic | SSE4.1 (128-bit) |
| `x86-64-v3` (default) | `x86-64-v3` | magic | AVX2 |
| `x86-64-v3-pext` | `x86-64-v3` + feature `pext` | PEXT | AVX2 |
| `x86-64-v4` | `x86-64-v4` | PEXT | AVX-512 |
| `aarch64` | `generic` / `apple-m1` | magic | NEON |

- `pext` is a separate Cargo feature because Zen 1/2 report BMI2 but run `pext` in slow microcode. `build.rs` fails the build if `pext` is set without `target_feature = "bmi2"`.
- Other Cargo features: `embed-net` (default), `large-pages`, `tune` (exposes search constants as UCI options for SPSA), `syzygy` (reserved).
- Runtime detection happens once in `main`: `is_x86_feature_detected!` checks every feature the binary was built for. A mismatch prints `info string` naming the right tier and exits, instead of dying with an illegal-instruction fault.

**`unsafe` policy.**

- `engine-uci`, `perft`, `datagen`: `#![forbid(unsafe_code)]`.
- `engine-core`, `engine-nnue`: `#![deny(unsafe_code)]`, with `#[allow]` only on the sites in the table below.
- `clippy::undocumented_unsafe_blocks` is denied; every block carries a `// SAFETY:` comment.
- The default is to remove bounds checks through types (`#[repr(u8)]` enums indexing exactly sized arrays). `unsafe` is added only where a profile shows a residual check.

| # | Site | Why | Invariant and enforcement |
|---|---|---|---|
| 1 | `attacks` slider lookup `get_unchecked(offset + idx)` | Hottest lookup in the engine | **Not taken so far.** The lookup is bounds-checked; removing the check measured about 3% in perft, within noise. Revisit with a search profile. If taken: `idx < 1 << bits` by construction of the shift, and const asserts already prove every square's range ends inside the 107,648-entry table. |
| 2 | `include_bytes!` blob to `&Network` | No startup initialisation, no lazy-init check | Wrapper is `#[repr(C, align(64))]`. Const assert on `size_of` equality. Element types are plain integers, so every bit pattern is valid. Little-endian targets only, enforced by `compile_error!`. The attack tables do not need this: `build.rs` emits them as Rust source. |
| 3 | `Square::from_index` (`transmute` from `u8`) | Bit-scan results and move fields to enum | The index is masked to 6 bits before the transmute, so every input is a valid discriminant; the function is safe to call. A const assert pins `Square` to discriminants 0..=63. `debug_assert!(i < 64)` catches callers relying on the mask. |
| 4 | `MoveList` slice views over `[MaybeUninit<ScoredMove>; 256]` | Avoid zeroing 2 KB per node | `push` writes through a bounds-checked index before incrementing `len`, so the first `len` elements are initialised and `len <= 256`; overflow panics instead of writing out of bounds. FEN parsing rejects material no game can reach, which keeps move counts under 256 (the legal maximum is 218). |
| 5 | TT allocation and `Send`/`Sync` for the raw table | Huge-page aligned allocation, multi-threaded clear | Layout has non-zero size, 2 MiB alignment. Zeroed memory is a valid `AtomicU64`. Freed with the same layout. Resizing takes `&mut self`, so the borrow checker guarantees no search is running. |
| 6 | TT prefetch | Hide the DRAM miss behind make | Pointer derived from an in-bounds index. Prefetch has no architectural side effects. |
| 7 | `engine-nnue::simd` loads and stores | Vectorised accumulator and output | Parents are `#[repr(align(64))]`. `const _: () = assert!(HIDDEN % 64 == 0)`. Features guaranteed by `cfg`. Value-range invariants are checked when a net is loaded (section 5). |

TT reads and writes themselves are safe Rust (section 4.2). Verification: Miri runs the engine-core tests in CI with the deep perft and exhaustive tests cut down or skipped. Sites 3 and 4 are exercised by the perft suite in debug builds, where the asserts are live.

## 2. Board representation and state management

### 2.1 Primitive types

```rust
#[repr(transparent)] #[derive(Copy, Clone, PartialEq, Eq)] pub struct Bitboard(pub u64);
#[repr(u8)] pub enum Square { A1 = 0, B1, /* … little-endian rank-file … */ H8 = 63 }
#[repr(u8)] pub enum Color { White = 0, Black = 1 }
#[repr(u8)] pub enum PieceType { Pawn, Knight, Bishop, Rook, Queen, King }
#[repr(u8)] pub enum Piece { WhitePawn = 0, BlackPawn, WhiteKnight, /* … */ BlackKing = 11 }
// discriminant = (piece_type << 1) | color; "no piece" is Option<Piece>, one byte via the enum niche
```

### 2.2 Position and BoardState

```rust
#[derive(Clone)]
#[repr(C, align(64))]
pub struct Position {
    // cache line 0 — occupancy
    pieces:  [Bitboard; 6],          // 48 B, by piece type
    colors:  [Bitboard; 2],          // 16 B
    // cache line 1 — mailbox
    mailbox: [Option<Piece>; 64],    // 64 B, square → piece
    // cache line 2 — state
    state:   BoardState,             // 64 B
}

#[derive(Copy, Clone)]
#[repr(C)]
pub struct BoardState {
    pub key:             u64,             // full Zobrist
    pub pawn_key:        u64,             // pawns only (pawn hash, pawn correction history)
    pub non_pawn_key:    [u64; 2],        // per colour (non-pawn correction history)
    pub checkers:        Bitboard,        // enemy pieces giving check
    pub pinned:          Bitboard,        // own pieces pinned to own king
    pub threats:         Bitboard,        // squares attacked by the opponent, own king removed from occupancy
    pub ep_square:       Option<Square>,  // 1 B via enum niche
    pub castling:        CastlingRights,  // u8 bitflags: WK WQ BK BQ
    pub halfmove:        u8,              // fifty-move counter, clamped on FEN input
    pub captured:        Option<Piece>,   // piece captured by the move that produced this position
    pub stm:             Color,
    pub plies_from_null: u8,              // repetition scan horizon
    pub fullmove:        u16,
}
const _: () = assert!(size_of::<BoardState>() == 64);
const _: () = assert!(size_of::<Position>() == 192 && align_of::<Position>() == 64);
```

Chess960 rook squares and the per-square castling-rights mask (`[u8; 64]`) are game constants. They live in a `CastlingInfo` held by `ThreadData`, not in the copied state.

### 2.3 Copy-make

```rust
impl Position {
    /// Writes the child into `out`; returns the piece deltas for the evaluator
    /// (the return value arrives with the NNUE in M7).
    pub fn make_into(&self, mv: Move, ci: &CastlingInfo, out: &mut Position) -> DirtyPieces;
    /// Returns the child by value; used by perft and tools.
    pub fn make(&self, mv: Move, ci: &CastlingInfo) -> Position;
    pub fn make_null_into(&self, out: &mut Position);
}
// search: let (lo, hi) = self.positions.split_at_mut(ply + 1);
//         let dirty = lo[ply].make_into(mv, &self.castling, &mut hi[0]);
```

Why copy-make wins at this size:

- **The irreversible state is already 64 bytes.** Incremental make/unmake would have to save and restore keys, en passant square, castling rights, clocks, captured piece, checkers, pins and threats on a side stack. The real saving is not writing two more cache lines, sequentially, into memory that is already in L1.
- **Unmake disappears.** Its branches on capture, en passant, castling and promotion mispredict more than they save. Null move becomes a copy plus three field edits.
- **The stack is small.** `Box<[Position; MAX_PLY + 4]>` with `MAX_PLY = 240` is 47 KB per thread. The parent is still hot when the child returns.
- **It removes the largest class of engine bugs** (make/unmake asymmetry) by construction.

`captured` is kept even though nothing needs undoing: capture history, recapture logic and the NNUE delta all read it.

Repetition detection uses a per-thread `keys: Vec<u64>` holding game history plus the search path. Capacity is reserved for `len + MAX_PLY` at `go`, so it never reallocates inside the search.

Zobrist keys are `const` tables from a `const fn` splitmix64 with a fixed seed: 12×64 piece-square, 16 castling, 8 en passant file, 1 side to move. The en passant key is XORed in only when an enemy pawn can actually capture, so transpositions hash identically.

### 2.4 Move encoding

```rust
#[repr(transparent)] #[derive(Copy, Clone, PartialEq, Eq)]
pub struct Move(NonZeroU16);     // size_of::<Option<Move>>() == 2
// bits 0–5 from | 6–11 to | 12–15 flag
// 0 quiet            1 double push      2 king-side castle   3 queen-side castle
// 4 capture          5 en passant
// 8–11 promotion N/B/R/Q                12–15 promotion-capture N/B/R/Q
// bit 14 = any capture (flags 4, 5, 12–15); bit 15 = promotion

#[repr(C)] pub struct ScoredMove { pub mv: Move, _pad: u16, pub score: i32 }   // 8 B, move list only
```

The move is 16 bits because it is stored in the TT, killers, countermoves and PV, where width costs memory. The combined history score exceeds `i16`, so the score stays out of the move. The all-zero pattern (a1 to a1, quiet) is never a move, which gives `Option<Move>` its niche for free.

## 3. Move generation and attack tables

### 3.1 Sliding attacks

```rust
struct Magic { mask: u64, magic: u64, offset: u32, shift: u32 }   // 24 B
static ROOK:    [Magic; 64];
static BISHOP:  [Magic; 64];
static SLIDERS: [u64; 107_648];            // 102,400 rook + 5,248 bishop = 841 KB

#[inline(always)]
pub fn rook_attacks(sq: Square, occ: Bitboard) -> Bitboard {
    let m = &ROOK[sq.index()];
    let idx = m.offset as usize + ((occ.0 & m.mask).wrapping_mul(m.magic) >> m.shift) as usize;
    Bitboard(SLIDERS[idx])       // with feature `pext` (M8): idx = offset + _pext_u64(occ, mask)
}
```

- **Magic numbers** are found once by `cargo xtask find-magics` and committed as constants. The build does no search.
- **The table** is produced by `build.rs`, not `const fn`. Evaluating 107,648 ray walks in the compiler's const interpreter slows every build. `build.rs` writes the tables as Rust source to `OUT_DIR`, which is pulled in with `include!`. That needs no `unsafe` and no endianness handling, and the tables sit in `.rodata` with zero startup cost. `build.rs` also fails the build if a magic number has a collision.
- **One generator, three consumers.** The ray walker lives in `attacks/tablegen.rs`. It is a module of the crate (unit tests compare table lookups against it), and it is included via `#[path]` by `build.rs` and by `xtask`.
- **PEXT** (M8) uses the same table size with a different fill order; `build.rs` reads `CARGO_FEATURE_PEXT`.
- **Small tables.** Knight, king and pawn attacks are `const fn`. `BETWEEN[64][64]` and `LINE[64][64]` (32 KB each) are generated by `build.rs` with the slider table.

### 3.2 Generation and legality

Generation is pseudo-legal, with legality checked lazily when a move is about to be played. The staged picker often cuts off on the TT move with nothing generated, so legality is paid for only on moves actually tried.

```rust
pub fn gen_noisy(pos: &Position, list: &mut MoveList);     // captures, en passant, queen promotions
pub fn gen_quiet(pos: &Position, ci: &CastlingInfo, list: &mut MoveList);   // includes underpromotions
pub fn gen_evasions(pos: &Position, list: &mut MoveList);  // only when checkers != 0
```

A move is noisy if it captures or promotes to a queen. Promotions to less than a queen that also capture are generated with the captures.

**Evasions.** With two checkers, only king moves are generated. With one, non-king moves are restricted to `BETWEEN[king][checker] | checker`, plus en passant when the checker is the pawn that just double-pushed.

**`pos.is_legal(mv)`**, using the precomputed state:

| Move kind | Test |
|---|---|
| King move | `!threats.contains(to)`. `threats` is computed with the king removed from occupancy, so stepping back along a checking ray is caught. |
| Castling | No square on the king's path is in `threats`. In Chess960, the castling rook must not be pinned. Path emptiness is checked at generation. |
| En passant | Explicit: remove both pawns, place the capturer, test rook and bishop rays from the king. Covers the horizontal discovered check. |
| Other | Legal if `from` is not in `pinned`; otherwise only if `LINE[king][from]` contains `to`. |

**`pos.is_pseudo_legal(mv)`** validates TT, killer and countermoves before use. A TT move can be garbage after a rare collision, and making an unvalidated move would corrupt the board. It is property-tested: for random positions and all 65,536 `u16` values, `is_pseudo_legal(m)` holds exactly when `m` is in the generated set.

`checkers`, `pinned` and `threats` are computed once at the end of `make_into`. `threats` also feeds history indexing.

### 3.3 Staged MovePicker

```rust
pub struct MovePicker {
    stage: Stage,
    tt_move: Option<Move>, killers: [Option<Move>; 2], counter: Option<Move>,
    list: MoveList,                    // 256 × 8 B
    cur: usize, end: usize, bad_end: usize,   // bad captures are compacted to list[0..bad_end]
    see_margin: i32, skip_quiets: bool,
}
enum Stage {
    TtMove, GenNoisy, GoodNoisy, Killer1, Killer2, Counter, GenQuiet, Quiet, BadNoisy,   // main search
    EvTt, EvGen, Evasion,                                                                 // in check
    QsTt, QsGen, QsNoisy,                                                                 // quiescence
    Done,
}
impl MovePicker {
    pub fn next(&mut self, pos: &Position, h: &History, ss: &StackView) -> Option<Move>;
    pub fn skip_quiets(&mut self);     // late move pruning: jump to BadNoisy
}
```

It is deliberately not an `Iterator`. `next` borrows position and history only for the call, so the recursive search can take `&mut ThreadData` in between.

Stage behaviour:

- **TtMove:** yield if `is_pseudo_legal`. No generation.
- **GoodNoisy:** score each capture as `16 · value[victim] + capture_history`. Before capture history exists, the tie-break is least valuable attacker. Selection-sort one move at a time. A move failing `see_ge(mv, -score / 32)` is swapped into the bad-capture region.
- **Killer1/2, Counter:** yield if quiet, pseudo-legal and not already yielded.
- **Quiet:** generate, score from the history tables, partially insertion-sort entries above `-3500 · depth`, and yield, skipping the TT move, killers and countermove.
- **BadNoisy:** yield the deferred captures in their existing order.

## 4. Search engine and pruning pipeline

### 4.1 Framework

```rust
pub struct ThreadData<E: Evaluator> {
    pub id: usize,
    positions: Box<[Position; MAX_PLY + 4]>,
    ss:        Box<[StackEntry; MAX_PLY + 8]>,   // offset by 4 so ss[ply - 4] is always valid
    keys:      Vec<u64>,
    eval:      E,
    hist:      Box<History>,
    castling:  CastlingInfo,
    root_moves: Vec<RootMove>,                   // move, score, previous score, PV, nodes spent
    nodes: u64, seldepth: u8, root_depth: i32, completed_depth: i32, nmp_min_ply: usize,
}
pub struct StackEntry {
    pub static_eval: i32, pub mv: Option<Move>, pub moved: Option<Piece>,
    pub excluded: Option<Move>, pub killers: [Option<Move>; 2],
    pub in_check: bool, pub tt_pv: bool, pub double_exts: u8, pub cutoff_count: u8,
    pub pv: PvLine,                              // [Option<Move>; MAX_PLY] + len
}
```

Scores are `i32` in the search and `i16` in the TT. `MATE = 32000`, `MATE_BOUND = MATE − MAX_PLY`, `INF = 32001`.

**Iterative deepening and aspiration.**

- For depth 5 and above, the window is `[avg − δ, avg + δ]` with `δ = 12 + avg² / 16384`.
- Fail low: `β = (α + β) / 2`, `α = max(avg − δ, −INF)`.
- Fail high: `β = min(avg + δ, INF)`, and the re-search depth drops by one, at most three times.
- After either: `δ += δ / 3`. Once `δ > 1000` the window is fully open.

**Node order in `search::<N>(ply, α, β, depth, cut_node)`:**

1. If `depth ≤ 0`, go to quiescence.
2. Stop check, then draw detection, then the `MAX_PLY` guard.
   - Repetition: one repetition inside the search tree, or two before the root, scanned over `min(halfmove, plies_from_null)`.
   - Also the fifty-move rule and insufficient material.
   - A draw returns `1 − (nodes & 2)`, a ±1 jitter against repetition blindness.
3. Mate-distance pruning.
4. TT probe. In non-PV nodes, cut off when `tt_depth ≥ depth`, the bound is compatible, there is no excluded move and `halfmove < 90`.
5. Static eval is the TT's stored eval or `evaluate()`, plus the correction-history adjustment. It is tightened by the TT score when the bound allows. `improving` means the static eval is above the one two plies earlier (four plies if that node was in check).
6. Whole-node pruning (4.4).
7. Internal iterative reduction: `depth ≥ 4`, no TT move, PV or cut node: `depth −= 1`.
8. Move loop: per-move pruning, extensions, make, TT prefetch, late move reductions with PVS re-search (4.4).
9. No legal move: mate (`−MATE + ply`) or stalemate. With an excluded move, return `α`.
10. Update histories, store to the TT (never with an excluded move), update correction history.

**Quiescence.**

- TT cutoff at any stored depth.
- Not in check: stand pat with the corrected static eval. Return it if `≥ β`; otherwise raise `α`.
- In check: no stand pat, and all evasions are searched.
- Otherwise noisy moves only; no quiet checks are generated.
- Per move when not in check: skip if `stand_pat + 200 ≤ α && !see_ge(mv, 1)`, and skip if `!see_ge(mv, 0)`.

### 4.2 Transposition table

```rust
#[repr(C)]            struct Slot    { data: AtomicU64, check: AtomicU64 }   // check = key ^ data
#[repr(C, align(64))] struct Cluster ([Slot; 4]);                            // exactly one cache line
pub struct TranspositionTable { ptr: NonNull<Cluster>, len: usize, generation: AtomicU8 }

// data word: 0–15 move | 16–31 score i16 | 32–47 static eval i16 | 48–55 depth + 7 (0 = empty)
//            56–57 bound | 58 was-PV | 59–63 generation (5 bits)
pub enum Bound { None = 0, Upper = 1, Lower = 2, Exact = 3 }

pub fn probe(&self, key: u64) -> Option<TtEntry> {
    for s in &self.cluster(key).0 {
        let d = s.data.load(Relaxed);
        if d != 0 && s.check.load(Relaxed) ^ d == key { return Some(TtEntry::unpack(d)); }
    }
    None
}
fn cluster(&self, key: u64) -> &Cluster {      // Lemire range reduction: any size, no power-of-two rule
    &self.slice()[((key as u128 * self.len as u128) >> 64) as usize]
}
```

**Why this layout.**

- Relaxed `AtomicU64` loads and stores compile to plain `mov`. The access path is safe Rust with no data-race undefined behaviour.
- A torn write (word 0 from one thread, word 1 from another) fails the XOR check and reads as a miss.
- Verification uses the full 64-bit key, so false hits from short keys are gone. That matters because TT scores drive cutoffs and singular extensions.
- The cost is density: 16 bytes per entry against the 10-byte, three-per-32-byte packing. That is accepted for correctness at high thread counts. The compact variant sits behind the same `probe`/`store` API as an M9 experiment.

**Allocation and resizing.**

- One contiguous `alloc_zeroed` with 2 MiB alignment, requested as huge pages where available (`MADV_HUGEPAGE`; `VirtualAlloc(MEM_LARGE_PAGES)` with fallback).
- On `setoption Hash`, the old table is freed before the new one is allocated. Peak memory is never doubled and nothing is allocated per entry.
- Clearing on `ucinewgame` is chunked across `Threads` scoped threads.
- `hashfull` samples the first 250 clusters for current-generation entries.

**Aging.** The generation is 5 bits, incremented per `go`. `age = (generation − entry_generation) & 31`. A probe hit from an older generation refreshes the generation.

**Replacement** in `store(key, mv, score, eval, depth, bound, pv, ply)`:

1. If a slot holds the same key:
   - Keep its move if the new move is `None`.
   - Overwrite when the bound is `Exact`, the entry is from an older generation, or `depth + 4 + 2·pv > old_depth`.
2. Otherwise replace the slot with the lowest `stored_depth − 8 · age`. Empty slots count as lowest.

**Mate scores** are stored relative to the node, not the root:

```rust
fn to_tt(s: i32, ply: i32) -> i16 {
    (if s >= MATE_BOUND { s + ply } else if s <= -MATE_BOUND { s - ply } else { s }) as i16
}
fn from_tt(s: i32, ply: i32, halfmove: i32) -> i32 {
    if s >= MATE_BOUND {
        if MATE - s > 100 - halfmove { return MATE_BOUND - 1; }   // mate lies beyond the fifty-move horizon
        s - ply
    } else if s <= -MATE_BOUND {
        if MATE + s > 100 - halfmove { return -MATE_BOUND + 1; }
        s + ply
    } else { s }
}
```

### 4.3 Move ordering and history

**SEE** is `pos.see_ge(mv, threshold) -> bool`, the swap algorithm on bitboards:

1. `balance = value(captured) + promotion_gain − threshold`. If negative, fail.
2. Subtract the moving piece's value. If still non-negative, pass.
3. Otherwise loop on the target square: take with the least valuable attacker of the side to move, set `balance = −balance − 1 − value(attacker)`, remove it from occupancy, and re-reveal x-rays (bishop attacks after a pawn, bishop or queen capture; rook attacks after a rook or queen capture).
4. A king may not capture while the opponent still has attackers.
5. The side that cannot continue profitably loses.

Values are 100/300/300/500/900. Castling returns `threshold ≤ 0`.

**Tables** (thread-local, `Box<History>`, about 1.3 MB):

```rust
pub struct History {
    main:    [[[[i16; 2]; 2]; 4096]; 2],        // [stm][from·64+to][from attacked][to attacked]
    capture: [[[i16; 6]; 64]; 12],              // [moved piece][to][captured type]
    cont:    [[[[i16; 64]; 12]; 64]; 12],       // [previous piece][previous to][piece][to]
    counter: [[Option<Move>; 64]; 12],          // [previous piece][previous to]
}
#[inline] fn gravity<const MAX: i32>(h: &mut i16, bonus: i32) {
    let b = bonus.clamp(-MAX, MAX);
    *h += (b - *h as i32 * b.abs() / MAX) as i16;       // |h| ≤ MAX is a fixed point; MAX = 16384
}
```

- Quiet ordering score: `main + 2·cont[ply−1] + cont[ply−2] + cont[ply−4] / 2`.
- Bonus `min(170·depth − 50, 1800)`; malus `min(150·depth − 30, 1500)`.
- On a quiet beta cutoff: bonus to the best move in `main` and `cont` at plies −1, −2 and −4; malus to every quiet searched before it; shift killers; set the countermove.
- On any cutoff: capture-history bonus if the best move is a capture, and malus to the captures searched before it.

**Correction history** is shared across threads (section 6.1). Tables are `[[AtomicI16; 16384]; 2]`, indexed by `pawn_key`, by each `non_pawn_key`, and by the previous move's piece and target square. The update runs when the node is not in check, the best move is quiet or absent, and the score does not contradict the bound direction:

`gravity::<1024>(entry, clamp((best − static_eval) · depth / 8, −256, 256))`

The correction applied is the weighted sum of the tables divided by 512.

### 4.4 Selectivity, extensions and reductions

Common guard for whole-node pruning: `!PV && !in_check && excluded.is_none()`.

| Technique | Exact condition | Action |
|---|---|---|
| Razoring | `depth ≤ 3 && eval + 250·depth < α` | `v = qsearch(α−1, α)`; return `v` if `v < α` |
| Reverse futility | `depth ≤ 8 && eval − 75·(depth − improving) ≥ β && eval < MATE_BOUND && β > −MATE_BOUND` | Return `(eval + β) / 2` |
| Null move | `depth ≥ 3 && eval ≥ β && static_eval ≥ β − 20·depth + 180 && ss[ply−1].mv.is_some() && has_non_pawn_material(stm) && ply ≥ nmp_min_ply && β > −MATE_BOUND` | Search at `depth − R` with window `(−β, −β+1)`, `R = 4 + depth/4 + min((eval − β)/200, 3)` |
| Null-move verification | Null search returned `≥ β` | If `depth < 14` or already verifying, return the score (capped to `β` if a mate score). Otherwise set `nmp_min_ply = ply + 3·(depth − R)/4`, run `search(β−1, β, depth − R)` with null move disabled, and return only if that also reaches `β`. |

Per-move pruning applies when `!ROOT && best > −MATE_BOUND && has_non_pawn_material(stm)`, with `lmr_depth = max(depth − LMR[depth][move_count], 0)`:

| Technique | Exact condition | Action |
|---|---|---|
| Late move pruning | `quiets_seen ≥ (3 + depth²) / (2 − improving)` | `picker.skip_quiets()` |
| Futility | Quiet, `!in_check`, `lmr_depth ≤ 8`, `static_eval + 100 + 90·lmr_depth ≤ α` | `picker.skip_quiets()` |
| SEE pruning, quiets | `depth ≤ 8 && !see_ge(mv, −25·lmr_depth²)` | Skip |
| SEE pruning, captures | `depth ≤ 6 && !see_ge(mv, −100·depth)` | Skip |

SEE pruning applies in PV nodes too. It is skipped only at the root and for the TT move.

**Extensions**, with a global guard of `ply < 2·root_depth`:

- **Singular.** Conditions: `!ROOT && depth ≥ 8 && mv == tt_move && excluded.is_none() && tt_depth ≥ depth − 3 && tt_bound ∈ {Lower, Exact} && |tt_score| < MATE_BOUND`.
  - Set `s_beta = tt_score − depth` and search `(s_beta − 1, s_beta)` at `(depth − 1) / 2` with `mv` excluded.
  - `v < s_beta`: extend 1. Extend 2 when `!PV && v < s_beta − 20 && ss.double_exts ≤ 6`.
  - Otherwise, `s_beta ≥ β`: **multi-cut**, return `s_beta`.
  - Otherwise, `tt_score ≥ β`: extend −1.
- **Check.** If singular gave no extension, the move gives check and `see_ge(mv, 0)`: extend 1.

**Late move reductions.** The table is `LMR[d][m] = 0.78 + ln(d)·ln(m) / 2.47` for `d, m` in 1..64, in fixed point ×1024. It is built once in `Shared`, so there is no global lazy static.

- Applies when `depth ≥ 2 && move_count > 1 + ROOT + PV`.
- Captures use the table value divided by 2.
- Adjustments: `+1` not improving; `+1` cut node; `−1` PV node; `−1` `tt_pv`; `−1` gives check; `−1` killer or countermove; `+1` TT move is a capture; `− history_score / 8192`.
- Reduced depth is `clamp(new_depth − r, 1, new_depth)`, searched with `(−α−1, −α)`.
- If the score beats `α` and a reduction was applied, re-search at `new_depth` with the null window. `new_depth` is adjusted by `+1` if `score > best + 40 + 2·new_depth` and `−1` if `score < best + new_depth`.
- In PV nodes, a full-window search follows for the first move or when the score beats `α`.

All these constants become `tune` parameters and are SPSA-tuned in M9.

## 5. Evaluation subsystem

### 5.1 Phase 1: bootstrap evaluator (`engine-core::hce`)

Its purpose is to validate the search and to label the first data generation. It is time-boxed and not polished.

- **Tapered score.** `S(mg, eg)` packs into one `i32` as `(eg << 16) + mg`. `phase = min(24, N + B + 2R + 4Q)`. `eval = (mg·phase + eg·(24 − phase)) / 24`, from the side to move, plus tempo.
- **Material and PSQT.** Tables written for Bear and computed in `const fn` from simple rules (centralisation, pawn advancement, rook on the seventh, king shelter in the middlegame and king activity in the endgame), recomputed from bitboards on each call.
- **Pawn hash**, per thread, 16,384 entries, indexed by `pawn_key`:

```rust
#[repr(C)] struct PawnEntry { key: u64, score: i32, passed: [Bitboard; 2], shelter: [i16; 2] }
```

- **Pawn terms:** isolated, doubled, backward, connected and phalanx by rank, passed by rank. All cached.
- **Passed pawn extras** (not cached): king distances, blocked stop square, rook behind, free path.
- **Mobility:** per-piece-type tables indexed by the count of reachable squares not attacked by enemy pawns.
- **King safety:** attack units from the count and weight of attackers on the king ring plus safe checks, through `units² / 4` capped. Pawn shelter and storm by file. Open and semi-open files near the king.
- **Small terms:** bishop pair, rook on open or semi-open file.
- **Tuning.** All weights sit in one `Params` struct. `datagen tune` runs Texel tuning (logistic loss, Adam) on positions from Bear's own self-play, which also replaces the hand-written numbers.

### 5.2 Phase 2: NNUE (`engine-nnue`)

Two networks, in order:

| | Net-1 (M7) | Net-2 (M9) |
|---|---|---|
| Shape | `(768 → 256)×2 → 1` | `(768×8 → 1024)×2 → 1×8` |
| Input buckets | None | 8 king buckets, horizontally mirrored |
| Output buckets | None | 8, by `(popcount(occupied) − 2) / 4` |
| Activation | SCReLU | SCReLU |
| King-move refresh | Never needed | Finny table |

Quantisation: `QA = 255` for the feature transformer, `QB = 64` for output weights, `SCALE = 400`, all `i16`.

```rust
pub const HIDDEN: usize = 1024;
const _: () = assert!(HIDDEN % 64 == 0);

#[repr(C, align(64))]
pub struct Network {
    ft_weights:  [[i16; HIDDEN]; 768 * KING_BUCKETS],
    ft_bias:     [i16; HIDDEN],
    out_weights: [[[i16; HIDDEN]; 2]; OUT_BUCKETS],     // [bucket][us, them]
    out_bias:    [i16; OUT_BUCKETS],
}
#[repr(C, align(64))] pub struct Accumulator { v: [[i16; HIDDEN]; 2] }   // [perspective]

pub struct DirtyPieces { adds: [(Piece, Square); 2], subs: [(Piece, Square); 2], n_add: u8, n_sub: u8 }
struct AccEntry { acc: Accumulator, dirty: DirtyPieces, computed: [bool; 2], king_moved: [bool; 2] }

pub struct Nnue {
    net:   &'static Network,
    stack: Box<[AccEntry; MAX_PLY + 4]>,
    top:   usize,
    finny: Box<[[FinnyEntry; KING_BUCKETS * 2]; 2]>,    // [perspective][mirror × bucket]
}
#[repr(C, align(64))]
struct FinnyEntry { acc: [i16; HIDDEN], pieces: [Bitboard; 6], colors: [Bitboard; 2] }
```

**Feature index** for perspective `p` and a piece `(colour, type, square)`:

`bucket(king_p) · 768 + (colour != p) · 384 + type · 64 + (square ^ (56 if p is black) ^ (7 if king_p is on files e–h))`

**Accumulator stack.** Updates are lazy.

- `push` only records `DirtyPieces` and clears `computed`. Nodes that cut off on the TT, or are in check, never pay for an update.
- `evaluate`, per perspective, walks back to the nearest computed ancestor, then applies fused updates forward: `add1_sub1` (quiet), `add1_sub2` (capture), `add2_sub2` (castling). Each reads the parent and writes the child in one pass.
- If the king crossed a bucket or mirror boundary for a perspective, that perspective is refreshed from its `FinnyEntry`. The cached bitboards are diffed against the current ones, the few adds and subs are applied to the cached accumulator, the cached bitboards are updated, and the result is copied onto the stack.

**Output:**

```
sum = Σ screlu(acc[us][i])·w[b][0][i] + Σ screlu(acc[them][i])·w[b][1][i]     // screlu(x) = clamp(x, 0, QA)²
eval = (sum / QA + out_bias[b]) · SCALE / (QA · QB)
eval = eval · (200 − halfmove) / 200, clamped inside ±(MATE_BOUND − 1)
```

**SIMD.** `std::arch` on stable. The module `simd::{avx512, avx2, sse41, neon, scalar}` is selected by `cfg(target_feature)` behind one set of `#[inline(always)]` functions. `scalar` is the reference implementation.

```rust
#[cfg(target_feature = "avx2")]
#[inline(always)]
pub fn screlu_dot(acc: &[i16; HIDDEN], w: &[i16; HIDDEN]) -> i64 {
    use std::arch::x86_64::*;
    // SAFETY: avx2 is statically enabled; both arrays sit at 64-byte-aligned offsets inside
    // #[repr(align(64))] parents; HIDDEN % 16 == 0, so every load is in bounds and aligned.
    unsafe {
        let (zero, qa) = (_mm256_setzero_si256(), _mm256_set1_epi16(QA as i16));
        let mut sum = zero;
        for i in (0..HIDDEN).step_by(16) {
            let x  = _mm256_load_si256(acc.as_ptr().add(i).cast());
            let wv = _mm256_load_si256(w.as_ptr().add(i).cast());
            let v  = _mm256_min_epi16(_mm256_max_epi16(x, zero), qa);
            // v·w fits i16 (255·127 = 32,385); madd then yields (v·w)·v as i32 pairs
            sum = _mm256_add_epi32(sum, _mm256_madd_epi16(_mm256_mullo_epi16(v, wv), v));
        }
        hsum_epi32_to_i64(sum)       // widen before the horizontal add
    }
}
```

**Numeric invariants**, checked when a net is loaded and by const asserts:

- Output weights lie in `[−127, 127]`, so `v·w` fits `i16`. The trainer clips to ±1.98.
- Feature-transformer weights lie in `[−505, 505]` with at most 32 active features, so the accumulator `i16` cannot overflow.
- Each `i32` lane accumulates at most `(HIDDEN/16)·2·255·127·255`, which fits for `HIDDEN ≤ 2048`. The cross-lane sum does not fit in the worst case, hence the `i64` widening.

**File format.** Header: `b"BEARNNUE"`, format version, architecture hash, `HIDDEN`, bucket counts. Then little-endian `i16` arrays padded to 64 bytes. The default net is embedded (unsafe site 2). `setoption EvalFile` loads an external file into an aligned heap `Network` after checking header and length.

**Training.**

- Data comes from `datagen`: self-play at a fixed 5,000-node soft limit, 8 to 10 random opening plies, win and draw adjudication.
- Positions are filtered to quiet ones: not in check, best move not a capture, score not near mate.
- Records are written in the trainer's own format so no loader has to be written.
- The trainer is `bullet`. Net-1 is trained on HCE-labelled games. Each later net is trained on games from the previous net.
- Budget: a few hundred million positions for Net-1, one to two billion for Net-2.
- Resource risk: about a billion positions is several days of generation on one desktop, and training realistically needs a CUDA GPU. Whether one is available is an open question; it only matters from M7.

## 6. Parallelism and the UCI loop

### 6.1 Lazy SMP

```rust
pub struct Shared {
    pub tt:        TranspositionTable,
    pub corr:      CorrectionHistory,              // AtomicI16 tables
    pub stop:      CachePadded<AtomicBool>,        // read-mostly, on its own line
    pub pondering: AtomicBool,
    pub nodes:     Box<[CachePadded<AtomicU64>]>,  // one slot per thread
    pub lmr:       LmrTable,
    pub time:      TimeManager,
}
pub struct Engine<E: Evaluator> { shared: Shared, threads: Vec<Box<ThreadData<E>>>, root: Position, /* options */ }

fn go(&mut self, limits: Limits) {
    let shared = &self.shared;
    let (main, helpers) = self.threads.split_first_mut().unwrap();
    std::thread::scope(|s| {
        for td in helpers {
            std::thread::Builder::new().stack_size(16 << 20)
                .spawn_scoped(s, move || td.iterative_deepening(shared, false)).unwrap();
        }
        main.iterative_deepening(shared, true);
        shared.stop.store(true, Relaxed);          // scope exit joins the helpers
    });
    let best = vote(&self.threads);
    // wait here while pondering or infinite and not yet stopped, then print bestmove
}
```

- **`thread::scope` per `go`.** Workers borrow `&Shared` and `&mut ThreadData` with no `Arc` and no `'static`. Histories persist across searches because the `Engine` owns them. The spawn cost per `go` is small next to any real time control.
- **Shared:** the TT and correction history. Correction history uses relaxed load and store on `AtomicI16`; a lost update is harmless and the gravity clamp keeps every write in range.
- **Thread-local:** position stack, search stack, key history, all move-ordering history, HCE pawn hash, NNUE stack and Finny tables.
- **Diversity** comes from TT interaction alone; every thread runs the same iterative deepening with no depth-skipping scheme.
- **Stack size matters on Windows**, where the main thread gets 1 MiB. No search ever runs on the process main thread; the coordinator and helpers get 16 MiB.

### 6.2 Coordination

- **Stop.** Every thread does `shared.stop.load(Relaxed)` when the low 10 bits of its node count are zero and after each root iteration. Only the main worker reads the clock, when `nodes & 2047 == 0`, and sets `stop` at the hard limit.
- **Node counting.** Each thread counts locally and publishes to its padded slot every 1,024 nodes. `info nodes/nps` sums the slots. `go nodes N` with one thread compares exactly every node, which bench and datagen determinism need.
- **Voting.** With `m = min score over threads`, each thread adds `(score − m + 14) · completed_depth` to its best move's tally. The winner is the best thread among those backing the top-tally move. A proven mate, or a shorter mate, overrides. PV and `bestmove ... ponder ...` come from the winner.

### 6.3 Time management

Inputs in milliseconds: `t = max(remaining − MoveOverhead, 1)`, `inc`, `mtg` (0 if absent).

```
base  = t / 20 + 3·inc / 4                         when mtg = 0
base  = t / (min(mtg, 40) + 1) + 3·inc / 4         when mtg > 0
hard  = min(4 · base, 0.75 · t)
soft₀ = min(0.65 · base, hard)
```

After each completed iteration on the main thread:

```
s = consecutive iterations with the same best move, capped at 10
Δ = previous iteration score − current score, in centipawns
p = nodes spent under the best root move / total nodes

f_stability = 1.30 − 0.05 · s                      → [0.80, 1.30]
f_score     = clamp(1 + Δ / 80, 0.75, 1.50)
f_nodes     = clamp(1.6 − 1.2 · p, 0.50, 1.40)
soft        = min(soft₀ · f_stability · f_score · f_nodes, hard)
```

- Stop between iterations when `elapsed ≥ soft`. Abort mid-iteration when `elapsed ≥ hard`.
- `go movetime x`: `soft = hard = x − MoveOverhead`.
- `go depth` and `go nodes` ignore the clock.
- `go infinite` and `go ponder` never stop themselves. If the search finishes early, the coordinator holds `bestmove` until `stop` or `ponderhit`, as the protocol requires.
- `ponderhit` clears `pondering` and the limits apply to time elapsed since `go`.

### 6.4 UCI parser and state machine

```rust
pub enum Command {
    Uci, IsReady, UciNewGame,
    Position { fen: Option<String>, moves: Vec<String> },
    Go(GoParams),     // wtime btime winc binc movestogo depth nodes movetime mate infinite ponder searchmoves
    Stop, PonderHit,
    SetOption { name: String, value: Option<String> },
    Quit,
    D, Perft(u32), Eval, Bench { depth: Option<i32> },      // debug extensions
}
pub fn parse(line: &str) -> Option<Command>;     // pure, unit-tested and fuzzed
```

**Two long-lived threads:**

- **Reader** (process main thread). Blocking `stdin.lock().lines()` and `parse`. It handles the search-critical commands itself through atomics: `stop` sets `stop`, `ponderhit` clears `pondering`, `quit` sets `stop` and closes the channel. Everything else goes down an `std::sync::mpsc` channel.
- **Coordinator** (16 MiB stack). Owns the `Engine`, drains the channel in order, runs `go`, and prints `info` and `bestmove`.

**`isready`.** The reader sets `searching` to true itself at the moment it forwards a `Go`, so there is no race window. If `searching` is true it answers `readyok` directly. If idle, it forwards `IsReady` down the channel so the reply comes after any pending `setoption` or `position`.

**States:** `Idle → Searching ⇄ Pondering → Idle`. `position`, `setoption` and `ucinewgame` during a search are ignored with an `info string`. Unknown tokens are skipped, as the specification says.

**Output** goes through one line-atomic writer. Only the main worker prints `info depth … seldepth … multipv … score cp|mate [lowerbound|upperbound] nodes … nps … hashfull … time … pv …`.

**Options:** `Hash`, `Threads`, `MultiPV`, `Ponder`, `Move Overhead`, `UCI_Chess960`, `EvalFile`, plus every search constant under the `tune` feature.

### 7.2 Strength validation

**Bench.** `bear bench [depth]` searches a fixed set of positions (24 at M2, growing to about 50) to a fixed depth on one thread, with all search state cleared between positions. The default depth is 6 at M2 and rises towards 12 as the search becomes more selective. It prints `<nodes> nodes <nps> nps`. The node count is the build's functional signature:

- It goes in every functional commit message as `Bench: <nodes>`.
- CI runs it on Linux and Windows and fails if it differs from the commit message, which also proves the two platforms agree. SIMD tiers are added to that check in M8.
- A commit claiming no functional change must leave it unchanged.

**SPRT** runs through `cargo xtask sprt --base <rev> --bounds gain`, which wraps:

```bash
fastchess -engine cmd=new/bear name=new -engine cmd=base/bear name=base -each tc=8+0.08 proto=uci option.Hash=16 option.Threads=1 -openings file=books/bear-8ply.epd format=epd order=random -rounds 20000 -games 2 -repeat -concurrency 14 -recover -sprt elo0=0 elo1=5 alpha=0.05 beta=0.05 -pgnout file=sprt.pgn
```

| Purpose | Bounds | When |
|---|---|---|
| Gain, early | `[0, 10]` | M3 to M5, where patches are worth tens of Elo |
| Gain, standard | `[0, 5]` | M6 onward, short time control |
| Gain, late | `[0, 3]` | Once typical gains fall below 3 Elo; `[0.5, 4.5]` also fits here |
| Non-regression or simplification | `[−5, 0]` | Refactors and feature removals |
| Long time control confirmation | Same bounds at 40+0.4 | Anything touching time management, extensions or reduction formulas |

α = β = 0.05 throughout.

**Openings.** `books/bear-8ply.epd` holds 2,000 distinct positions made by `datagen openings`: eight random legal moves from the start, kept only if nobody is in check and Bear's own depth-5 search scores the position within 60 centipawns of level. It is Bear's own data, so it carries no third-party terms.

- **Rule:** no functional search or eval change merges to `main` without a passed SPRT. Non-functional changes need an unchanged bench.
- **Lazy SMP changes** are tested at `Threads=4`, 8+0.08.
- **Absolute strength** is measured at milestone boundaries by a gauntlet against a fixed pool of engines with published ratings. The 3000+ target is on the CCRL Blitz scale, single thread. It counts as met only when the lower end of the gauntlet's 95% interval is above 3000.
